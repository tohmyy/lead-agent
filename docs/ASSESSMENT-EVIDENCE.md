# Assessment Evidence Checklist

This is the capture checklist for `docs/BUILD-PLAN.md` §59 ("Phase 19 — Assessment Evidence"), written against this app's actual screens, tables, and files rather than the abstract build-plan list. Work through it top to bottom during (or right after) the controlled demo run described in `docs/DEMO-SCRIPT.md`.

Free evidence that doesn't need a live run already exists at `docs/evidence/screenshots/` (Dashboard, New Run form, and every tab of the seeded example run — generated by `npm run evidence:screenshots`, see the bottom of this doc). Everything else below needs a real controlled run against live Apify/Firecrawl/Anthropic credentials.

## Before you start

Run the **Production Smoke Test** checklist in `docs/DEPLOYMENT.md` first if you haven't already (steps 1–10: create a small run, `qualifiedTarget: 1`, `discoveryLimit: 2`, and confirm each stage completes). That same run doubles as your evidence-capture run — no need to run it twice. Once it looks healthy, either keep it small for evidence purposes or create a second run at `qualifiedTarget: 10` per `docs/BUILD-PLAN.md` §55 for the real assessment submission.

Save everything you capture under `docs/evidence/` (gitignored — see `.gitignore`), organized however is convenient, e.g. `docs/evidence/screenshots/`, `docs/evidence/supabase/`, `docs/evidence/exports/`.

## Application evidence

| What | Where |
| --- | --- |
| Working application URL | The deployed URL (see `docs/DEPLOYMENT.md`), or `http://localhost:3000` for a local capture |
| New run | `/runs/new` — screenshot the filled-in form (objective, qualified lead target, discovery maximum) before submitting |
| ICP review | `/runs/[id]` → **ICP** tab — screenshot the refined ICP (hard filters, soft signals, target personas, reasoning) and the Approve action |
| Research activity | `/runs/[id]` → **Activity** tab — screenshot the human-readable event feed; expand the "Tool call log" `<details>` panel for the technical view |
| Qualified leads | `/runs/[id]` → **Leads** tab — screenshot the lead list and at least one expanded lead showing fit reasons, concerns, and confidence |
| Outreach review | `/runs/[id]` → **Outreach** tab — screenshot the 3-step email sequence and LinkedIn message for a qualified lead, including the review-state controls |
| Run overview / cost | `/runs/[id]` → **Overview** tab — screenshot the Progress and Research limits cards (shows qualified/discovered counts and recorded discovery/agent spend) |

## Agent evidence

| What | Where |
| --- | --- |
| Tool calls | `tool_calls` table in Supabase (see below), and the expandable "Tool call log" panel on the Activity tab — each row has `tool_name`, `purpose`, `status`, `duration_ms`, and `error_message` if any |
| Agent reasoning/output | `leads.qualification_reasoning`, `leads.fit_reasons`, `leads.concerns` (Supabase or the Leads tab) — this is the agent's evidence-backed reasoning, not a raw model transcript |
| Skill usage | `src/agents/skills/load-skills.ts` — screenshot or reference this file to show which of the 5 skills (`outreach-safety` always, plus `icp-refinement`, `lead-qualification`, `outbound-copywriting`, `lead-list-quality` per turn) get embedded in the system prompt for each agent turn |
| Qualification decisions | `leads.qualification_status` + `leads.hard_filter_results` per lead (Supabase or Leads tab) — shows the pass/fail verdict against each approved hard filter |

## Supabase evidence

Screenshot each table (Table Editor or a `select *` in the SQL editor) for the run you just executed:

```text
runs
run_icps
discovered_companies
leads
lead_sources
tool_calls
run_events
outreach_drafts
```

A quick way to confirm the full audit chain for one run:

```sql
select id, status, qualified_target, discovery_limit, qualified_count,
       discovered_count, discovery_cost_usd, agent_cost_usd
from runs where id = '<run-id>';
```

## Safety evidence

| Control | Where to point |
| --- | --- |
| Discovery limits | `run.discovery_limit` on the Overview tab, enforced server-side (not just in the New Run form) — `src/application/discovery/discovery-service.ts`. `MAX_DISCOVERY_LIMIT` in `.env.local`/`docs/DEPLOYMENT.md` is the hard ceiling regardless of what any run requests |
| Apify cost controls | The Overview tab's "Discovery spend" / "Agent spend" figures (from `discovery_cost_usd`/`agent_cost_usd`, added in `supabase/migrations/005_operator_workflow.sql`), and the provider-readiness check on `/runs/new` (`src/lib/config/provider-readiness.ts`) that tells the user upfront whether discovery/research providers are actually configured before they create a run |
| Human approval | The **Approve & start search** action on the ICP tab — no paid discovery happens before this click (`src/application/runs/run-orchestrator.ts`: `refineIcp()` stops at `awaiting_icp_approval`) |
| Outreach review gate | Outreach tab review-state controls (`not_reviewed` → `reviewed`/`edited` → `approved_for_export`) — there is deliberately no "Send" button/action anywhere in the codebase |
| Untrusted website content | Architectural, not a single test: `src/agents/tools/research-website-tool.ts` returns scraped content as tool *output* (data returned to the model), never as instructions injected into the system prompt; `src/agents/skills/outreach-safety.md` is the standing skill that tells the agent to treat page content as untrusted. Worth calling out in the Loom narration (see `docs/DEMO-SCRIPT.md`) since there isn't a dedicated automated test for this one yet |
| SSRF protection | `src/lib/security/url-safety.test.ts` — automated tests reject unsupported URL schemes, `localhost`, and IPv6 loopback before any fetch; enforced by `src/lib/security/url-safety.ts`, called from the research adapter before every outbound request |
| Secret protection | `src/lib/config/env.ts` is guarded by `import "server-only"`; `src/lib/logging/sanitize.test.ts` covers redaction of secrets from tool-call logs |

## Outreach Sample Pack

Once you have at least one qualified lead with approved outreach, generate the pack:

```text
GET /runs/<run-id>/export/outreach.md
```

(or `?scope=all` to include drafts not yet marked `approved_for_export`). The route (`src/app/runs/[id]/export/outreach.md/route.ts`) already emits everything `docs/BUILD-PLAN.md` §60 asks for per lead: company, objective, source context, qualification reasoning, fit reasons, concerns, all 3 email steps, and the LinkedIn message. Save the downloaded file into `docs/evidence/exports/` as the submission's Outreach Sample Pack.

## Free screenshots (seeded data, no paid API calls)

```bash
npm run db:seed              # creates the example run — no paid API calls
npm run dev                  # in a separate terminal
npm run evidence:screenshots # captures docs/evidence/screenshots/*.png
```

This walks the seeded example run (1 qualified lead, approved ICP, outreach drafts, run events already populated by `scripts/seed.ts`) and screenshots the Dashboard, New Run form, and every Run Workspace tab. It's a good stand-in for the Application evidence above while you're preparing to record the real Loom, but it should be supplemented with screenshots from an actual live run before final submission — the seeded run has no real tool-call history.
